## 2026-08-21 v1.6.0 热重载全链路修复（首次真正打通）

**背景**：热重载（编辑器改配置 → 保存/推送 → 路由器 OpenClash 生效）从未正常过。本次全链路定位并修复。

- `backend/server.js`（源码）与 `clash-editor-native/server.js`（运行实例）同步改：
  1. scpTo/scpFrom 由 `scp` 改为 **SSH cat**（spawn + stdin 流，二进制安全）——路由器无 sftp-server，scp 必失败是推送从未成功的根因

- `frontend/src/views/MainPage.vue`：applyOpenClash 按 reloaded/reloadError 分级提示

## 2026-08-23 v1.6.2 规则编辑 MATCH 位置 + reload 分支 payload 修复

**背景**：用户用编辑器添加 xvideos 规则后不生效。根因两个：
1. 前端 `RuleTable.vue` 添加规则用 `newRules.push(ruleStr)` → 直接 append 到数组末尾。若 MATCH 兜底不在数组最后（或新增规则在 MATCH 后），规则成死代码永不匹配。实测 xvideos 被 push 到 MATCH 之后 → 内存里没有。
2. 后端 `server.js` `/api/router/reload` 的 openclash 分支还是 path 方式重载 config/ 源（`{path: '/etc/openclash/config/<name>.yaml'}`）→ 丢 dns/tun 段 → 全 LAN DNS 断网风险。push 分支 08-21 已改 payload 合并，reload 分支漏了。

**改动文件**：
- `frontend/src/components/RuleTable.vue`：saveRule 新增规则时找 MATCH 索引，`splice(matchIdx, 0, ruleStr)` 插到 MATCH **之前**；无 MATCH 才 append
- `backend/server.js`（源码）+ `clash-editor-native/server.js`（运行实例）同步：reload 分支改 payload 合并方式（SSH cat 读 root 运行副本 + config/ 源 → merged → yaml.dump → PUT /configs payload），与 push 分支一致
- 前端 build（vite）→ 新产物 index-DVQhnJ9o.js + index-1SWAYLNV.css → 部署到运行实例 public/assets/ + index.html 更新引用

**验证（全过）**：
- 前端 build 成功（1498 modules，6.8s）
- 运行实例 node --check 语法 OK；3000 重启后 HTTP 200、新产物 200
- reload API 实测 → `{"success":true,"output":"openclash TAG: HTTP 204"}`（payload 方式）
- reload 后内核：xvideos 在第 68 位（MATCH 前）→ 👆 手动切换、tun.enable:true、策略组 18 个完好、Clash 进程健康
- config 源 + 模板 TAG.tpl 同步 xvideos（模板原来没有，订阅更新会丢；现已补，放在 MATCH 前）

**踩坑**：
1. 源码仓库 server.js 与运行实例已分叉（源码旧 ini 模板输出 vs 运行实例 TOML 新版）——修 reload 必须**分别 patch 两个文件**，不能整体覆盖
