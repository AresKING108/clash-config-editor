# clash-config-editor 开发日志

## 2026-08-21 v1.6.0 热重载全链路修复（首次真正打通）

**背景**：热重载（编辑器改配置 → 保存/推送 → 路由器 OpenClash 生效）从未正常过。本次全链路定位并修复。

**改动文件**：
- `backend/server.js`（源码）与 `clash-editor-native/server.js`（运行实例）同步改：
  1. scpTo/scpFrom 由 `scp` 改为 **SSH cat**（spawn + stdin 流，二进制安全）——路由器无 sftp-server，scp 必失败是推送从未成功的根因
  2. `/api/router/reload` 补 openclash 分支（原只有 subconverter 分支，openclash 假成功）；subconverter 服务名改 `subconverter-extended`（旧名 init.d 已删）
  3. `/api/router/subconverter-status` 端口 36611 → 25500（源码）；并对 HTML 欢迎页提取版本号
  4. push 的 triggerReload 重写：secret/端口**动态解析**（root 副本 + uci `dashboard_password` 兜底，不硬编码）；改用 **path 方式**重载 config/ 源文件（`PUT /configs {"path": ...}`，实证 204+生效）；失败返回 honest 错误不再假成功
  5. push 的 yaml 规范化：external-ui 修正 + **provider path 规范化**（`./providers/` → `./proxy_provider/`，OpenClash 约定，错误路径会导致节点丢失/网络异常）
  6. push 只推 **config/ 源目录**（root 运行副本由 OpenClash 管理，不再覆盖，避免 secret 断链）
- `frontend/src/components/RouterSync.vue`：pushOpenClash/oneClickDeploy 改读 Pinia store 的 currentFile（原硬编码文件名、与 store 脱节）；一键部署 = 保存+推送+重载；pushSubconverter 禁用（旧 ini 格式废文件，待 TOML 改造）
- `frontend/src/views/ConfigEditor.vue`：保存后可选「推送并热重载」勾选框（localStorage 记忆，仅 openclash_*.yaml 生效）
- `frontend/src/views/MainPage.vue`：applyOpenClash 按 reloaded/reloadError 分级提示
- 本地 `configs/openclash_TAG.yaml`：provider path 修正为 `./proxy_provider/`
- 版本号 1.0.0 → **1.6.0**（三个 package.json）

**验证结果（2026-08-21 实测）**：
- `GET /api/router/status` → `{"connected":true,"info":"OK aarch64 GNU/Linux"}`
- `GET /api/router/subconverter-status` → `{"version":"1.4.6"}`（25500）
- 推送临时文件 → 路由器 md5 与本地一致（SSH cat 传输）
- `POST /api/router/reload {service:"openclash"}` → `openclash TAG: HTTP 204`
- `POST /api/router/push`（TAG 配置 + triggerReload）→ `{"pushed":1,"reloaded":true}`；内核 `/proxies` 确认新节点加载、`mihomo -t` test successful
- 页面 3000 → HTTP 200

**踩坑记录**（本轮）：
1. scp -O 在路由器仍不可靠 → 必须 SSH cat
2. 本地配置无 secret 字段 → reload 认证 401；内核 secret 稳定（mihomo 重载不丢），权威来源是 OpenClash uci `/etc/config/openclash` 的 `dashboard_password`
3. OpenClash `/etc/init.d/openclash restart` 输出 "Already Stop!/Already Start!" 假成功（不干活）
4. push 覆盖 root 运行副本会导致 secret 断链 → 只推 config/ 源目录
5. provider path 用错目录（./providers/）会导致 provider 节点丢失 → 推送时强制规范化
6. GET /configs 响应不含 proxies 明细，验证配置加载要用 GET /proxies

**遗留**：save-as-template 的 TOML 输出改造（独立待办）；pushSubconverter 按钮待 TOML 模板链路恢复后启用。

## 2026-08-21 v1.6.1 triggerReload 丢 dns 段修复

**Bug**：热重载（应用修改）用本地文件内容做 payload → 本地文件无 dns 段 → 内核重载后 7874 端口消失 → dnsmasq 劫持转死端口 → DNS/网络全断（实测 google/baidu 全 000）。

**修复**（backend/server.js + 运行实例同步）：
- triggerReload 的 payload 改为**合并配置**：SSH cat 读运行副本 `/etc/openclash/<name>.yaml`（OpenClash 注入的 dns(7874)/secret/tun 段）→ js-yaml 解析 → 以运行副本为基础、本地用户顶层键（proxies/proxy-groups/rules 等）覆盖 → dump 完整 YAML 做 payload → PUT /configs
- 保留 external-ui 修正、secret 动态解析（preSecret 兜底 uci dashboard_password）

**验证（全过）**：
- push+triggerReload → {pushed:1, reloaded:true}（payload 合并方式 204）
- 重载后：7874 在监听、nft clash 规则 12 条、google 204、baidu 200、fw4.lock 已清理
- 用户修改的 proxy-groups 重载后内核 /proxies 可见（验证组已清理恢复）
- 内核 /version meta 正常

**踩坑**：
1. mihomo 的 PUT /configs path 有 SAFE_PATHS 限制（仅 /etc/openclash 等），/tmp 不行
2. proxy-group 必须含 proxies 或 use（空组 → 400 "use or proxies missing"）
3. fw4.lock 可能是 watchdog 重建防火墙遗留死锁（0 字节无进程持有），rm 清理安全
